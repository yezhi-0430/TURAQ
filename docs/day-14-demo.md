## 真实模型验收与压缩响应修复

用户完成登录后，页面显示 Qwen 在线模型。通过网页发送假设价格从 10 元变为 9 元、要求调用 `calculate_change` 的问题。页面显示“请求未完成 / Agent 执行失败，请稍后重试”，没有伪装成成功。

只读检查确认正式数据库已有审计所需字段，失败请求没有新增工具审计。随后对同一账号通过正常 `admit` 额度/租约控制直接调用后端 `chat` 复现，异常链为 `HTTPException(500) → httpx.DecodingError → zlib.error`，发生在 `deadline_post` 重新构造 HTTP 响应时。没有打印密钥或修改业务数据；真实调用会正常消耗额度。

原因：`response.aiter_bytes()` 已解压正文，重新构造响应时却保留 `Content-Encoding`，HTTPX 再次解压而失败。`app/model_limits.py` 现在移除已失效的压缩、正文长度及传输分帧头，再用已解压正文构造响应；仍按解压后的大小限制 1 MiB，并保留状态码、内容类型等其他头。

按 TDD 新增 5 个压缩响应案例：gzip/deflate × HTTP 200/429 四例首先全部因重复解压失败；解压后大小限制一例在修复前已通过。修复中一次变量命名遮蔽被测试与 Ruff 检出，改为独立的 `decoded_headers`。最终运行：

```powershell
.\.venv\Scripts\python.exe -m pytest --confcutdir=tests/auth tests/auth/test_limits_deadline.py tests/auth/test_limits.py --tb=short
.\.venv\Scripts\python.exe -m ruff check app/model_limits.py tests/auth/test_limits_deadline.py
```

结果：24 passed，两个既有 Starlette/httpx/anyio 弃用提示；Ruff 通过。测试使用模拟 HTTP transport 和隔离 SQLite，不请求真实模型。

修复后再次通过同一后端入口及正常额度控制调用真实 Qwen，得到：

- `run_id=a7d7f87a-1c31-470c-8dfe-d73436cb52a0`
- `status=completed`，`rounds=2`
- `calculate_change` 参数：`previous_close=10`、`current_close=9`
- 工具成功，结果 `change_percent=-10.0000`
- 来源 `python_calculation`，输入来源 `tool_arguments`，没有交易日期
- 最终模型答案已返回；审计提交成功后循环才进入下一轮并完成

这证明修复后的真实后端调用链完成，不等于浏览器最终展示验收完成。刷新网页后回到登录窗口，等待用户再次进入工作台；未将直接调用结果注入网页。截至此处真实请求共三次研究运行：网页失败一次、诊断复现失败一次、修复后成功一次。
