# 8 周 AI Agent 开发实习冲刺计划

## 1. 目标与项目

时间：8 周，每天约 6 小时，总投入约 336 小时。

求职定位：Python / AI 应用开发 / Agent 开发实习生。

主项目：**A 股自选股风险监控与模拟交易 Agent**。

项目只服务个人研究，不提供真实交易，不预测确定性涨跌，不接入券商账户。Agent 只能生成模拟操作建议，必须经用户确认后，确定性的模拟交易引擎才能修改账户。

最终作品需要证明五类能力：

1. Python 后端与数据库能力。
2. 原生大模型 API、结构化输出与工具调用。
3. RAG、来源引用和金融信息核验。
4. LangGraph 状态工作流与 Human-in-the-loop。
5. 测试、评估、日志、Docker 和项目讲解能力。

## 2. 每天固定节奏

- 09:00–10:30：学习当天所需知识，只学马上要用的内容。
- 10:45–12:15：完成小练习或复现核心模块。
- 14:00–16:00：开发主项目。
- 16:15–17:15：测试、修复、重构。
- 17:15–17:45：Git 提交、学习记录和第二天任务。

规则：每天必须产生代码或文档提交；连续看教程不得超过 90 分钟；AI 生成的关键代码必须能逐行解释。

## 3. 技术范围

主栈：Python、FastAPI、Pydantic、SQLAlchemy、PostgreSQL、Pytest、国内可用大模型 API、LangGraph、Chroma 或 Qdrant、Streamlit、Docker。

数据策略：

- 公告和财报以交易所、巨潮资讯及上市公司披露文件为一级事实来源。
- 日线行情可先用 AkShare 或 Tushare 做学习和演示，但必须保存来源及采集时间，并允许导入本地样例数据。
- 新闻只作为线索来源，不能单独支撑重大风险结论。
- 开发和测试使用固定样例数据，避免测试依赖实时网络。

八周内不学：PyTorch 训练、模型微调、复杂前端、分钟级行情、高频策略、自动选股、真实交易、QMT、多 Agent 集群。

## 第 1 周：后端与工程基础

目标：完成一个有数据库、测试和清晰结构的自选股服务。

### 第 1 天：项目和 Git

- 创建代码仓库、虚拟环境和依赖管理。
- 设计 `app`、`tests`、`docs`、`data` 目录。
- 配置 `.gitignore`，禁止提交 `.env`、密钥和数据库文件。
- 写项目目标、非目标、用户故事和第一版架构图。
- 验收：仓库可安装、可启动、README 能说明项目要解决什么问题。

### 第 2 天：FastAPI 复习

- 复习路由、路径参数、查询参数、请求体、响应模型和状态码。
- 编写健康检查、股票查询和自选股增删改查接口。
- 使用 Pydantic 校验股票代码、市场和分组名称。
- 验收：在 `/docs` 中完整调用接口，非法输入返回明确错误。

### 第 3 天：数据库与 SQL

- 学习表、主键、外键、索引、事务和常用 SQL。
- 使用 SQLAlchemy 建立 `stocks`、`watchlists`、`watchlist_items`。
- 完成数据库迁移或初始化脚本。
- 验收：重启服务后数据仍存在，同一股票不能重复加入同一分组。

### 第 4 天：分层与异常处理

- 将 API、业务逻辑和数据库访问分开。
- 增加统一异常响应、日志和配置管理。
- 用环境变量保存数据库地址与模型密钥。
- 验收：数据库错误、重复添加和不存在的股票都有可读错误。

### 第 5 天：测试

- 学习 Pytest、fixture、参数化测试和 FastAPI TestClient。
- 测试自选股新增、删除、重复添加和非法股票代码。
- 创建独立测试数据库。
- 验收：核心接口测试通过，测试不访问互联网。

### 第 6 天：第一版界面

- 使用 Streamlit 制作自选股分组、股票列表和添加表单。
- 界面只调用 FastAPI，不直接操作数据库。
- 展示空状态、加载状态和错误状态。
- 验收：用户可以通过页面维护多组自选股。

### 第 7 天：周复盘

- 清理重复代码，补全 README 和接口说明。
- 录制 1 分钟演示：创建分组、添加股票、刷新页面。
- 用 10 分钟口述 FastAPI 请求如何进入数据库。
- 周验收：`pytest` 全通过，其他人能按 README 在本地运行。

## 第 2 周：原生大模型应用与最小 Agent

目标：不用 Agent 框架实现一个可测试的工具调用循环。

### 第 8 天：大模型 API 基础

- 学习 system/user/assistant/tool 消息、Token、上下文和流式输出。
- 封装统一模型客户端，不在业务代码中散落 API 调用。
- 实现超时、有限重试和错误映射。
- 验收：可切换测试假模型与真实国内模型。

### 第 9 天：结构化输出

- 使用 Pydantic 定义风险摘要：事实、推断、未知信息、风险等级、来源。
- 要求模型返回符合 Schema 的数据。
- 处理解析失败和字段缺失。
- 验收：20 条样例输入均不会因 JSON 格式错误导致服务崩溃。

### 第 10 天：Function Calling

- 编写 `get_stock_profile`、`get_daily_prices`、`calculate_change` 三个工具。
- 工具参数必须校验；金融计算使用 Python，不交给模型心算。
- 记录每次工具名称、参数、结果和耗时。
- 验收：模型能选择工具，错误参数不会执行。

### 第 11 天：最小 Agent Loop

- 自己实现“模型决定工具 → 执行工具 → 返回结果 → 模型总结”的循环。
- 设置最大步数、超时和明确终止条件。
- 防止重复调用同一工具形成死循环。
- 验收：能回答“比较两只股票最近 5 个交易日波动”，最多在限定步数内结束。

### 第 12 天：会话与审计

- 建立 `sessions`、`messages`、`tool_calls` 表。
- 保存对话、工具调用和最终结果。
- 实现历史截断或摘要策略。
- 验收：刷新页面后可恢复历史，能查看一次回答使用过哪些工具。

### 第 13 天：安全边界

- 明确工具白名单、参数限制和数据来源标记。
- 把“建议”与“执行”设计成不同数据类型和接口。
- 编写提示注入样例，保证文档内容不能修改系统权限。
- 验收：模型无法通过文本直接修改自选股或模拟账户。

### 第 14 天：第二个可演示版本

- 把最小 Agent 接入网页工作台。
- 展示回答、工具执行轨迹、来源时间和错误信息。
- 为 Agent Loop 编写单元测试，真实模型只做少量人工验收。
- 周验收：能够不看代码画出 Agent Loop，并解释为什么需要最大步数和工具校验。

## 第 3 周：拆解开源 Agent 并独立复现

目标：实践视频中的前两步：理解项目设计，再关闭源码复现核心模块。

### 第 15 天：选择并运行参考项目

- 选择 Nanobot 或另一个体量适中的开源 Agent，仅选一个。
- 跑通官方最小示例，记录安装和运行问题。
- 写清项目目标、入口和主要模块。
- 验收：可以用 3 分钟说明项目解决了什么问题。

### 第 16 天：架构阅读

- 追踪一条用户请求从入口到模型、工具再到结果的完整路径。
- 画模块图、时序图和状态变化图。
- 让 Coding Agent 辅助解释，但逐项到源码中验证。
- 验收：文档中每个结论都有对应源码位置。

### 第 17 天：工具和 Agent Loop

- 阅读工具注册、参数 Schema、调用分发、结果回传和终止逻辑。
- 与自己第 2 周实现对比，列出至少 5 个设计差异。
- 写一份取舍说明：哪些设计适合你的项目，哪些不需要。

### 第 18 天：会话、记忆和错误恢复

- 阅读上下文管理、会话持久化、重试和异常传播。
- 故意让工具失败，观察系统如何处理。
- 验收：能区分会话历史、长期记忆和业务数据库。

### 第 19 天：关闭源码复现

- 不查看参考实现，从空目录复现最小 Agent：工具注册、循环、会话和轨迹。
- 只实现参考项目中真正理解的功能。
- 为循环终止、未知工具和工具异常写测试。

### 第 20 天：对照与修正

- 将复现版本与原项目比较。
- 修复由理解错误造成的问题，而不是复制原代码。
- 写“我从参考项目学到了什么”文档。
- 验收：能够现场增加一个新工具并解释注册流程。

### 第 21 天：迁移到主项目

- 将有价值的工具抽象、轨迹记录和错误模型迁入金融项目。
- 不复制参考项目的业务无关框架。
- 周验收：形成开源拆解文档、独立复现仓库或子目录，以及可展示测试。

## 第 4 周：真实金融数据与风险规则 MVP

目标：完成不依赖大模型也能工作的风险监控基础。

### 第 22 天：数据契约

- 定义股票、日线、公告、新闻线索、风险事件的统一模型。
- 每条记录保存 `source_url`、`published_at`、`collected_at`。
- 准备 3–5 只股票的固定样例数据。
- 验收：相同数据重复导入不会生成重复记录。

### 第 23 天：日线行情适配器

- 为 AkShare 或 Tushare 编写独立适配器，并提供 CSV 备用适配器。
- 实现交易日缺失、接口超时和空数据处理。
- 验收：断网时测试仍可使用固定数据运行。

### 第 24 天：公告与财报导入

- 首版支持手动导入本地 PDF 和填写官方来源链接。
- 提取标题、公司、公告日期、报告期和正文。
- 保留原文件哈希，避免重复导入。
- 验收：至少导入三家公司的年报或公告样例。

### 第 25 天：价格和成交量规则

- 实现单日涨跌异常、成交量相对均值异常、连续涨跌、阶段新高/新低和波动率上升。
- 阈值配置化，并记录触发所用数据。
- 使用固定价格序列测试边界。

### 第 26 天：公告风险规则

- 识别减持、监管问询、业绩预警、重大诉讼、停复牌等关键词事件。
- 规则只生成“待研究线索”，不直接输出投资结论。
- 验收：每条事件包含触发原因、证据片段和严重程度初值。

### 第 27 天：定时扫描

- 实现每日扫描任务和手动刷新入口。
- 保证重复执行不重复创建风险事件。
- 保存任务开始、结束、成功数、失败数和失败原因。

### 第 28 天：风险中心 MVP

- 页面按股票、类型、风险等级和日期筛选事件。
- 展示数据来源、更新时间和规则证据。
- 周验收：关闭大模型后，系统仍能扫描样例数据并稳定生成风险事件。

## 第 5 周：RAG 与带证据的公司研究

目标：让 Agent 基于公告和财报回答，并能追溯到原文。

### 第 29 天：文档解析质量

- 比较普通 PDF 与表格较多 PDF 的解析效果。
- 保留页码、章节标题、公司和报告期等元数据。
- 建立解析失败报告，不静默丢失页面。

### 第 30 天：切分与索引

- 对标题、正文和表格使用合适的切分策略。
- 建立 Chroma 或 Qdrant 索引，只选一个。
- 测试不同块大小对召回的影响并记录结论。

### 第 31 天：检索

- 实现关键词与向量混合检索。
- 支持公司、文档类型和报告期过滤。
- 返回内容、页码、来源链接和相关度信息。

### 第 32 天：引用式回答

- 回答中的关键事实必须引用文档与页码。
- 检索不到证据时明确回答“现有资料不足”。
- 区分原文事实、程序计算和模型推断。

### 第 33 天：财务计算工具

- 实现同比、复合增长率、毛利率、经营现金流趋势等确定性函数。
- 使用 `Decimal` 处理金额，明确单位。
- 测试缺失值、负数、零分母和单位不一致。

### 第 34 天：基础 RAG 评估

- 为 3 家公司编写至少 30 个问题及标准证据位置。
- 评估检索命中、引用正确、数字正确和拒答是否合理。
- 记录错误属于解析、切分、召回、排序还是生成。

### 第 35 天：公司研究页

- 展示公司概览、指标趋势、相关风险和财报问答。
- 所有重要结论可以打开来源。
- 周验收：完成一次“比较两年营收、毛利率与经营现金流并列出风险”的演示。

## 第 6 周：LangGraph 研究工作流与人工确认

目标：完成从风险线索到模拟建议的可追踪 Agent 工作流，并开始投递。

### 第 36 天：LangGraph 基础

- 学习 State、Node、Edge、条件分支和 Checkpoint。
- 把第 2 周原生 Agent Loop 画成状态图。
- 仅在确实需要状态和分支的地方使用 LangGraph。

### 第 37 天：研究工作流

- 建立“理解问题 → 选择数据 → 检索 → 计算 → 核验 → 生成报告”节点。
- 每个节点输入输出使用明确的类型。
- 验收：可查看一次任务经过了哪些节点。

### 第 38 天：交叉核验与失败分支

- 一级来源缺失时禁止生成高置信度结论。
- 工具超时、文档缺失和数字冲突走明确失败或降级分支。
- 限制重试次数，支持从 Checkpoint 恢复。

### 第 39 天：风险评级

- 将规则证据、公告事实、财务趋势和来源质量组合成可解释评级。
- 模型可以解释评级，但不可任意改变确定性评分。
- 验收：相同输入产生稳定的基础评分与可追踪解释。

### 第 40 天：模拟操作建议

- 建议类型限定为观察、模拟买入、模拟减仓、模拟清仓。
- 输出建议理由、反方理由、未知项和失效条件。
- 建议只进入 `pending` 状态，不能修改账户。

### 第 41 天：Human-in-the-loop

- 用户可确认或拒绝建议，并填写理由。
- 确认前重新校验建议状态和报价时间。
- 完整记录 Agent 建议、用户决定和前后状态。

### 第 42 天：第一轮投递

- 部署当前版本，准备项目截图和 2 分钟演示。
- 简历加入项目、技术栈、个人职责和可量化结果。
- 开始投递 Python、AI 应用、Agent、RAG 相关实习，每日记录岗位要求。
- 周验收：至少完成首轮定向投递，不等第 8 周才开始找工作。

## 第 7 周：模拟交易、复盘和工作台

目标：形成类似视频所展示的完整产品闭环，但不接入真实交易。

### 第 43 天：模拟账户模型

- 建立账户、现金、持仓、订单、成交和账户快照。
- 默认资金 100,000 元，可配置。
- 所有金额使用 `Decimal`，禁止浮点金额计算。

### 第 44 天：模拟成交规则

- 约定使用指定交易日收盘价或下一交易日开盘价，首版只选一种并写清楚。
- 计算手续费、滑点、可用资金和持仓成本。
- 拒绝资金不足、持仓不足、重复确认和无效交易日。

### 第 45 天：确认到成交

- 将已确认建议转换为模拟订单。
- 执行成功或失败都写入审计日志。
- 保证同一建议最多成交一次。

### 第 46 天：持仓与收益

- 计算持仓盈亏、已实现盈亏、账户净值和最大回撤。
- 页面展示当前持仓、成交记录和净值曲线。
- 用手工算例验证结果，不依赖模型判断。

### 第 47 天：研究快照

- 在建议产生时冻结当时的数据、引用、提示词版本和模型信息。
- 新数据出现后不覆盖历史判断。
- 支持从一次交易回到当时的完整证据链。

### 第 48 天：复盘中心

- 对比当时建议、用户决定、后续价格和新风险事件。
- 评估提醒是否及时、引用是否正确、建议条件是否失效。
- 盈亏只是一项结果，不作为 Agent 正确性的唯一指标。

### 第 49 天：完整工作台

- 整合市场概览、自选股、风险中心、公司研究、Agent、模拟交易和复盘。
- 修复导航、空状态、加载状态和长文本显示问题。
- 周验收：从新增自选股到扫描、研究、确认、模拟成交和复盘完整走通。

---

## 第 8 周：评估、部署与面试

目标：把“能运行的项目”变成“能证明能力的求职作品”。

### 第 50 天：自动化评估

- 扩展到至少 50 个固定评估样例。
- 统计风险事件识别、检索命中、引用正确、数字正确、工具成功和合理拒答。
- 保存基线结果，防止后续修改导致退步。

### 第 51 天：安全与权限

- 测试提示注入、越权工具调用、恶意文档、超长输入和非法股票代码。
- 确保 Agent 不能跳过确认，也不能调用未注册工具。
- 日志不得记录 API Key 或其他密钥。

### 第 52 天：性能与成本

- 记录每个工作流节点的延迟、Token 和失败率。
- 对检索、提示词和缓存做一次有数据支持的优化。
- 在 README 中说明优化前后变化。

### 第 53 天：Docker 与部署

- 使用 Docker Compose 启动 API、数据库、向量库和界面。
- 提供示例环境变量文件和样例数据初始化方式。
- 在全新环境按 README 验证启动流程。

### 第 54 天：作品材料

- 完成架构图、数据流图、核心功能截图和 3 分钟演示视频。

## 4. 最低交付标准

以下项目必须全部完成，才能写进简历：

- 多自选股分组及日线数据导入。
- 可重复执行的风险扫描规则。
- 公告/财报 RAG 和页码引用。
- LangGraph 研究流程及失败分支。
- 待确认建议与人工确认。
- 确定性的模拟账户和一次性成交保护。
- 审计轨迹、评估集、自动测试和 Docker 启动。
- README、架构图、演示视频和在线或本地可运行版本。

时间不足时按顺序舍弃：新闻聚合、复杂市场概览、漂亮图表、多模型切换、自动通知。不得舍弃测试、引用、人工确认、数据时间戳和 README。

## 5. 每周验收问题

每周日必须回答：

1. 本周交付了哪个用户可见能力？
2. 哪部分是确定性代码，哪部分由模型完成？
3. 最严重的失败场景是什么，系统如何处理？
4. 有哪些自动测试证明它不是偶然跑通？
5. 如果面试官要求现场修改一个功能，我能否独立完成？

只要其中两项答不上来，下周第一天先补齐，不继续堆功能。
