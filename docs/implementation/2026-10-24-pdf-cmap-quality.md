## Evidence and design

Known CMB2024 physical14/15 uses Type0 Identity-H fonts, missing ToUnicode, descendant CIDSystemInfo Adobe/GB1/supplement4. Local pypdf6.20.1 treats CID bytes as UTF16BE, giving zero Han characters. Existing isolated pdfminer.six20260107 maps CID0x108F to营; its full text extraction restores Chinese but separates table labels/columns. An in-memory ToUnicode using standard AdobeGB1 mapping restores pypdf layout rows without changing original PDF; font CIDSet subsets805/1637entries reduce extraction from~.35s to~.02-.04s/page. Only CID0(.notdef) lacks a standard mapping in those subsets. FontTools is absent but not the cause of the proven CID/Unicode confusion.

Choose a standard-map compatibility layer, not company/word/value replacements. Keep pypdf layout and numeric grouping. Add pinned pdfminer.six20260107 for local standard Adobe CID maps (no parser/runtime upgrade). Whitelist Adobe GB1/CNS1/Japan1/Korea1 plus Identity-H/V. Existing ToUnicode is never overwritten. Use embedded CIDSet when present (<=8192bytes), otherwise bounded standard mapping; never load PDF-supplied paths/modules. Prepare only fonts used by text-show operators, traverse used Form XObjects with inherited resources and q/Q font state; reject cycles/depth/resource-budget overflows. PDF bytes remain read-only; only fresh reader font objects gain generated ToUnicode streams. Per-document preparation state records repaired fonts/pages.

Pure quality checks flag substantial replacement characters, unresolved CID markers, or highly mixed unexpected script output; plain English, numbers, legitimate single-script Arabic and short/symbol pages are not rejected merely for lacking Han. Unsupported used Identity fonts/missing maps/partial CID maps fail with safe error instead of usable facts. Keep original20MiB/1500pages/8MiB-page/768MiB-child/45sec-parent bounds. Do not promise OCR; unsupported/image-only files retain explicit unavailable errors. Preserve safe errors and pass new parser version/per-page extraction provenance, without exporting document text to observability.

Integrate with app.document_parser.extract, retaining compact normalization; analysis upload/disclosure child callers obtain the fix for new parses. Do not silently rewrite existing cached pages/indices or old frozen references: those need fresh extraction/reindexing. Existing known-report bypasses remain historical.
