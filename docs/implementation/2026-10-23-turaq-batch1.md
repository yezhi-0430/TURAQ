# TURAQ 第一批实施设计与计划（2026-10-23）

目标：本地固定资料评测、完整性门槛、当前机制基线、可关闭 Langfuse 元数据导出，以及批次发现留存。真实研究质量与真实成本不在本批离线成绩中推断。

设计：独立 evaluations/turaq 保存合成冻结资料、案例清单和仅评分器可读的 gold；app/research_eval.py 经真实 agent loop / review_step 执行预设模型案例，保存逐案例输出、异常与指纹。全部预期案例均进入分母；任务失败、评分失败、缺案例、重复案例、缺必要评分分别记录并使验收失败。生成器只接收 case.input。默认本地运行不联网。

方案取舍：采用小型自有 runner 加可选 Langfuse SDK 5.0.4 元数据桥接；不引入整个实验运行时或自托管栈。追踪经有界后台队列，失败/满队列丢弃且计数，不等待业务；只导出随机 ID、状态、计数、允许的 usage，禁止提示、回答、工具参数、资料、用户身份、异常文本。SDK 延迟导入，默认关闭。SDK 实验记录由本地实验汇总导出为 span 与 scores，不使用同步 task runner。

步骤：
- [x] 1. 写回归测试并复现 reduce 后逐批发现不可追查；保留 batch_findings / reduction_history，资料换版时清空，旧快照标明缺失。
- [x] 2. 测试并实现固定案例 runner、版本/文件指纹、完整性校验、离线 baseline；金标准只参与评分。
- [x] 3. 测试并保留模型每次请求 usage（含重试、失败未知值）；实现默认关闭的有界元数据导出与 SDK 适配。
- [x] 4. 运行隔离后端测试、前端现有检查、静态检查；保存真实输出和使用说明；检查 diff，不提交、不推送。

验收：错误工具可反馈恢复；轮数/期限生效；长文所有字符与批次发现可回查；来源/证券/期间由独立规则核对；缺评分不得放大成功率；追踪失败不改变业务结果；无 usage 不填 0。

执行记录：用户要求在当前项目直接完成，保留所有原有未跟踪项；在当前 checkout 新建 codex 分支以保留交接报告，不复制私人资料、不提交。单人顺序执行，最终独立自审。测试通过 --confcutdir=tests/unit 隔离根 conftest 的 PostgreSQL 自动清表 fixture。


实施结果：原始留存回归先得到2个 KeyError，随后修复通过。新增独立最终审查发现3项P2，均增加复现并修复：生产 report_period 字段、临时财报客户端 usage 生命周期、CLI 退出导出队列。针对性17项通过；当前合成机制基线7/7，真实模型质量未运行。SDK 5.0.4 在 uv 隔离环境中以全部 HTTP mock 验证，没有安装到业务环境或部署服务。完整命令、限制与验收结果见 evaluations/turaq/README.md。

取舍：本地 collector 保留最近256次原始 usage，不实施永久计费账本；CLI 导出最多等2秒，未完成显式记录，不影响本地评测分数。缺跨请求财报 trace 关联、真实公开财报 held-out 集与真实 Langfuse 服务端验证，作为下一批边界；不声称质量提升或生产外部服务已验收。未提交、推送或部署。
