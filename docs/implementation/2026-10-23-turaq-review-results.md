# TURAQ 第一批 review 与第二步验收

日期：2026-10-23。范围：第一批所有业务改动、新增未跟踪代码/测试与评测资料；包括独立只读 reviewer、主执行者复现和修复。所有重要发现已加失败测试并修复，没有剩余已确认的重要问题。未验证事项不等于已经证明没有问题。

## 发现与修复

| 发现 | 影响 | 修复与证据 |
|---|---|---|
| 空 expected / 空结果可 acceptance=true | 空跑冒充通过 | assess 要求非空唯一预期ID，校验行结构、错误和必要评分；空集回归先失败后通过 |
| 只验状态轮数，不验计算结果或最终回答 | 999% 错误仍能通过计算案例 | gold 增加独立预期工具结果、工具错误类别和固定回答，错误结果/答案注入被拒绝 |
| 生成侧文档与evidence共同篡改能自证 | 自报文本拼接相等无法证明冻结原文 | gold 保存冻结文档 hash，文档本体和证据同时改动也不能过 |
| 页码/offset/hash、批游标与归档摘要漏验 | 引用错误页、失效定位或被改写的批次发现仍通过 | 逐页连续覆盖、片段位置/文本/hash、游标与消耗字符数、汇总输入输出重放全部检查 |
| 错误恢复历史可省略 | 没有证据证明错误进入下一轮模型请求 | 要求完整轮数历史，并逐错误核对下一轮工具反馈及错误类别；删历史/清空/删反馈均拒绝 |

这些是评测假阳性，不表示生产交易计算器已被发现算错。真实模型研究质量从未用这批合成分数证明。旧报告的7/7不能和新评分器分数直接比较。

## 下一步已实现

app/research_compare.py 可对本地 baseline / candidate 报告独立重新评分，拒绝仅修改聚合成功率的伪通过。检查双方与当前冻结清单、评分器源码及版本、输入提示、工具schema、运行模式相符；应用代码指纹可不同，以支持真实代码候选对照。缺案例、重复案例、缺必要评分、任务/评分异常、损坏记录、版本不兼容或任意逐案例退化均拒绝。保持基线中的失败作为失败，不删除分母；候选必须全部通过，其他案例改善不能抵消退化。

兼容自对照只输出 no_mechanism_regression；可接受的改善仅称 mechanism_improved。automatic_promotion=false，任何结果都不表示真实研究质量提升。此工具验证报告内容的内部一致性，不提供执行真实性签名或不可信Python执行沙箱。

评分器升级为 contract-v2；gold和manifest同步升版。results/batch1-contract-v1.json 保留第一批历史报告；archive/contract-v1 保存与该报告hash逐字节匹配的旧冻结资料。旧版本应用源码未新增永久代码快照，历史报告主要用于追查；需重跑旧版本时仍要取得相应应用源文件。current.json 是新评分器当前基线。

实跑证据：self-comparison-v2.json 接受自对照；injected-bad-candidate-v2.json 明确标为人工故障注入（非模型运行），rejected-comparison-v2.json 检出 tool-calculate-v1 退化、自报评分不一致并拒绝，CLI退出1。这不是改进候选的真实质量实验。
