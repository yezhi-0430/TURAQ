# 研究助手：截图问题的原因与修复

## 原因

原来的 `get_daily_prices` 只查询 `daily_prices` 本地表，没有接入行情源。贵州茅台的基础股票名称与代码存在，但截图中的 2024-01-01 至 2024-05-31 日线未入库，所以工具成功返回空列表。Qwen 在线模型连接与行情连接是两个独立环节。基础资料记录不能证明行情、财报或公告完整；空列表也不能证明股票停牌或风险为零。

研究回答原来用 `textContent` 原样输出，导致 Markdown 的 `**`、列表标记等没有排版。

## 本次行为

- 已通过模型准入的 Qwen 会话在现有日线工具中使用在线 reader，固定请求腾讯财经公开历史日线；假模型保持本地离线模式。查询不向数据库写入行情或修改自选。
- 使用完整代码及明确日期闭区间，最大 366 个自然日/次，每次研究最多 4 个不同区间；请求缓存仅属于本次研究。响应最大 1 MiB，单次行情最多 8 秒且受原有请求剩余期限限制，超时关闭连接。
- 复用现有 K 线字段验证，过滤请求范围外的数据；在线价格为不复权，成交量明确区分手与股。返回记录数量、实际起止交易日、来源、采集时间、覆盖限制；不保证返回覆盖全部交易日。
- 首末实际返回日收盘价变化由程序计算。有效空响应标记 `no_data`；异常响应、网络故障或超时回退本地。无本地记录则明确返回获取失败，不伪装为空数据成功。回退的来源、采集时间、复权口径与成交量单位未知，不计算未经确认口径的区间涨跌幅。
- 来源由执行器根据服务端实际结果构造，模型文本不能认证来源。保留原有模型额度、权限、审计与执行限制。系统提供当前上海日期，要求区分基础股票资料与完整分析资料。
- 仅助手的非错误回答采用有限 Markdown 排版，支持标题、加粗、列表、表格、代码和引用。使用 DOM 与 `textContent` 创建内容，原始 HTML 与图片不执行；链接只接受无凭据的 HTTP(S)，新标签使用 `noopener noreferrer`。原始文本仍用于对话历史。

## 后续截图：行情成功后的模型超时

查阅本机真实调用审计与后端日志确认：2026-10-13 18:29 的旧日线请求返回本地空列表；18:31 的新请求已经从在线行情源取回 98 条记录，耗时 413.2ms，随后 `/agent/chat` 返回 504。因此新请求的失败发生在行情工具完成之后，并非仍未接通行情。配置当时单次模型调用只有 10 秒；长工具结果交给模型后，需要为生成回答保留更充足的时间。

另外，前端在新请求开始与失败时没有覆盖右侧运行信息，所以超时后仍显示上一轮股票基础资料查询“已完成”。

本次调整：

- 默认及本机单次模型等待为 30 秒（现有允许上限），总研究仍为 60 秒，额度、租约、模型并发与超时取消保持原规则。不自动重复提交模型请求。
- 超时仍返回 HTTP 504。若本请求已经成功提交工具审计，可同时返回请求内的运行编号与工具结果，明确标记 `incomplete`，不返回完整答案或动作建议；不会查询或混入其他请求的审计记录。
- 前端经过账号 revision 校验才接收部分结果，展示已查询事实与来源，失败消息不进入下一轮模型对话历史。开始、失败与恢复均更新本次研究卡片，不能沿用上一轮完成状态。
- 模型单次等待耗尽与总研究期限耗尽的提示区分；服务端记录运行 ID、用时与已审计工具数，不记录用户资料或密钥。
- 研究跳转改为最近 90 个自然日的日线行情，系统明确当前日期和旧回答不能代替新工具结果。

验证使用隔离模型和测试传输，不额外调用用户的付费 Qwen。已复现并覆盖“行情查询成功、随后模型超时”的 API/页面流程，以及失败恢复和账号切换后的迟到响应。生产页面的桌面和手机验收图为 `docs/visual-qa/assistant-timeout-desktop.png`、`assistant-timeout-mobile.png`；截图均明确标注测试夹具。

本轮最终回归：Python 600 项通过、前端 54 项通过、Ruff 通过、Vite 构建通过，生产页面桌面与手机验收通过。Python 仍排除上述既有旧导入测试文件，保留两项 Starlette 依赖弃用警告；新代码只读审查无明确重要问题。

延长等待时间减少过早终止，但外部模型慢响应仍可能触发单次或整体期限。旧回答不会因更新代码而改写；刷新页面、新建对话后重试可获得当前代码行为。
