# 爬虫数据存储与内存分析报告

## 一、数据量估算

### 单次爬取数据量

假设自选股列表：10只股票

**每天每只股票爬取：**
- 实时行情：1条 × 500字节 = 0.5 KB
- 公司公告：5条 × 2 KB = 10 KB
- 资金流向：1天 × 500字节 = 0.5 KB
- 合计：约 11 KB/股票/天

**10只股票每天：**
- 10 × 11 KB = 110 KB/天

**板块热点：**
- 热门股票：1条 × 5 KB = 5 KB/天

**每天总数据量：**
- 约 115 KB/天

## 四、内存使用分析

### ChromaDB内存特点
- **不是全部加载到内存**
- 使用 SQLite + 向量索引
- 查询时才加载相关数据

### 内存使用预测

| 文档块数 | 内存使用（估算） | 说明 |
|---------|----------------|------|
| 152 | ~50 MB | 当前 |
| 5,000 | ~200 MB | 1年后 |
| 15,000 | ~500 MB | 3年后 |
| 50,000 | ~1.5 GB | 10年后 |

**结论：** 内存不会爆，因为：
1. ChromaDB不会把所有数据加载到内存
2. 只有查询时加载相关向量
3. 3年内内存占用 < 500 MB

## 五、优化建议

### 方案1：定期清理（推荐）

保留策略：
- 最近1个月：全部保留
- 1-3个月：每周保留1天
- 3个月以上：每月保留1天

**效果：**
- 数据量减少 70%
- 保留关键信息

### 方案2：数据归档

按时间分库：
- `chroma_db_2024/` - 2024年数据
- `chroma_db_2025/` - 2025年数据
- `chroma_db_current/` - 当前月数据

**查询时：**
- 优先查当前月
- 需要历史数据时查归档库

### 方案3：只保留重要数据

过滤规则：
- 实时行情：只保留收盘价（不保留盘中）
- 公告：只保留重要公告（业绩、分红、重组）
- 资金流向：只保留主力大幅流入/流出的日期

**效果：**
- 数据量减少 80%

## 六、推荐方案

### 短期（启动阶段）
- **不做处理**
- 1年内数据量完全可控（350 MB）
- 服务器标配（50GB硬盘，4GB内存）完全够用

### 中期（1年后）
- **实施方案1：定期清理**
- 写一个清理脚本
- 每月运行一次
- 保留策略如上

### 长期（3年后）
- **根据实际情况选择：**
  - 用户多：升级服务器（8GB内存，100GB硬盘）
  - 用户少：方案1定期清理

## 九、结论

**直接回答您的问题：**

❌ **内存不会爆**

**原因：**
1. ChromaDB是磁盘数据库，不全部加载到内存
2. 每天新增数据很小（115 KB）
3. 1年累计 < 350 MB，完全在可控范围内
4. 3年累计 < 1 GB，标配服务器可承受

**建议：**
- **现在：** 什么都不用做，直接运行
- **1年后：** 评估数据量，考虑定期清理
- **3年后：** 根据用户量决定清理或升级

**不需要担心内存问题！**
