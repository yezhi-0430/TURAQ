# OpenViking 与现有系统组合

本次接入的是 OpenViking 0.5.2 的原生文件存储、文件检索和跨会话的主动保存偏好。现有系统继续处理登录权限、证券与披露时间过滤、证据排序、原文位置验证、模型额度和严格评分。服务不可用时财报评测回退到本地证据选择，研究对话忽略不可用偏好并继续。

## 使用

前后端入口为 `http://localhost:3000`。登录后进入 **系统设置 → 研究与风险**，在“长期研究偏好”中主动保存回答详略、页序引用和原表单位偏好。该区域使用独立的保存、刷新和清除按钮；普通设置页底部的保存按钮不保存这三个选项。

保存后，下一次研究请求会读取本账号的偏好。偏好以用户数据加入对话，不能覆盖系统权限、事实或评分。不会自动归档聊天记录，也不自动提取私人记忆。清除会把当前偏好记录置空并读回确认，下次对话不再使用；这不是对 OpenViking 文件版本历史的物理擦除。

现有财报质量评测会将已注册公开报告的当前授权页面保存到 OpenViking，按指标词语检索。首批仅覆盖原有茅台、平安两份固定报告的 7 个授权页面；不代表全文接入，未注册的私人上传文件不会进入此存储。该机制不改变金标、评分器或财务规则评分。

## 启动与关闭

在项目根目录运行：

```powershell
.venv/Scripts/python.exe scripts/launch_context_store.py
.venv/Scripts/python.exe scripts/launch_context_store.py --status
.venv/Scripts/python.exe scripts/launch_context_store.py --stop
```

首次启动需要已经存在的隔离运行环境 `.local-backups/openviking-runtime`，固定版本为 0.5.2。启动器只管理本项目的专用服务；端口冲突会报错，不终止其他程序。进程在后台运行，冷启动最多等待 120 秒。

专用原生服务监听 `127.0.0.1:1934`，本地拦截与控制服务监听 `127.0.0.1:1935`。启动成功会备份原 `.env` 并设置 `OPENVIKING_ENABLED=true`、本机地址和本地服务密钥。日志、密钥、原生存储和配置备份位于 Git 忽略的 `.local-backups/context-store/`，不可提交或分享整个目录。

彻底停用应用集成时在 `.env` 中设置 `OPENVIKING_ENABLED=false`。现有财报评测仍可用；该开关不删除已有原生存储。运行环境、存储和配置密钥应一起保留，随意换存储或账户会使旧偏好无法读取。

## 调用与核验边界

- 本版不调用原生语义检索、自动摘要或会话提交。文件写入使用 `defer_processing=true`；清除偏好同样使用延迟处理的空记录。
- OpenViking 初始化目录仍可能发起向量请求。这些请求在本地拒绝，状态中的 `rejected_model_requests` 单独计数；它们不是已完成的向量索引。此专用实例不能用于语义搜索。
- 子进程去除代理和外部模型密钥，并明确绕过本机代理；模型端点固定到本地拒绝服务。应用先核对带随机挑战的服务签名，再发送原生密钥或写入资料。外部模型调用为零，不应把拒绝计数解释成云模型用量。
- 每个登录账号对应独立原生账户。前端不能指定账户、资源路径、服务地址或密钥；接口沿用已有 Cookie 与 CSRF 检查。
- 检索 URI 必须属于本次已授权上下文，整页文本必须与当前原文完全一致。返回的片段仍经原证据 ID 机制和严格评分器验证。版本变化、缺失、检索无结果或原生服务故障均会回退。
- 单次原生请求最多 2 秒，单个上下文操作最多 6 秒；研究偏好读取最多 2 秒，且计入原研究总时限。回退情况可在评测响应的 `context_retrieval` 中查看。

真实原生服务验收命令为 `python -m scripts.verify_context_combination`。它只使用两个保留的合成账户与现有公开样本，不连接业务数据库，不调用云模型。验收会重启专用服务，先直接读取全部已保存页面核验持久化，再进行其他操作；测试偏好在最后置空。结果不是新的模型准确率。
