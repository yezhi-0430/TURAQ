# 邮箱注册、多人邀请码与用户数据隔离设计

日期：2026-10-11。状态：讨论稿，待用户审阅；未开始实现，未部署。

## 1. 已确认的目标与实现建议

用户准备上线供其他人注册使用，采用邮箱密码注册、邀请码内测。邀请码可以供多个不同账号使用。对上一轮推荐的名额规则，用户答复“可以”：本稿据此采用默认 50 人、7 天有效，可增加名额或撤销。

实现建议：项目内建立账号系统，先完成认证与所有权，再接建议确认及上线保护。SMTP 是可替换的发信接口，不绑定具体供应商。用户目前没有发信服务；接通真实服务并验收送达，是开放内测的前置条件。讨论中的默认值均可通过受限管理配置调整。

## 2. 当前代码中的实际缺口

- Watchlist 没有 owner_id，原手动 CRUD 与新 Agent 动作接口没有登录检查。
- /api/v1/market/watchlist 汇总全部 WatchlistItem，必须按当前用户过滤。
- Agent 聊天会返回 suggestions，但前端只保存 answer、executions，尚无建议确认交互，也未展示 source。
- HTTP Agent 工具审计没有用户归属；目前查询能力主要在仓储及命令行，不能直接成为跨用户查询入口。
- 前端多个脚本硬编码 http://localhost:8888；Vite 代理指向 8000；CORS 使用通配来源。内测需统一 API 路径与实际部署来源。
- 现有部署草稿使用 DATABASE_URL、ANTHROPIC_API_KEY，与实际 Settings 的数据库分项配置及 Qwen 配置不一致；不能直接视为已验证上线方案。
- Day12 对话持久化与刷新恢复仍未完成，本设计不会宣称已经具备。

## 3. 模块边界与交付顺序

A：账号、邀请码、邮件验证、密码找回、可撤销会话、所有权及必要登录界面；保护全部现有私有入口。

B：研究来源展示、建议卡片、用户确认、独立执行请求、失败与超时状态以及执行审计。

C：共享数据库限流和模型额度、生产配置、实际发信及双账号浏览器验收。A、B、C 全部通过才开放外部内测。

每一阶段分别安排实施与验收，避免把剩余风险监控、模拟交易、完整设置中心一起塞入本轮。不增加短信、第三方登录、支付、组织共享、完整管理员后台或会话历史功能。

## 4. 邀请码与注册

- 邀请码由受限管理命令生成，不提供匿名生成入口。管理员权限只能由服务端维护，注册请求不得指定管理员身份。
- 码使用密码学安全随机数；库中保存摘要，不存可直接使用的明文。管理命令仅在创建时返回明文，由用户自行分享；不自动发给其他人。
- 每码默认 max_uses=50、有效期 7 天，支持增加上限和撤销。增加上限不得低于已使用数量；续期需要明确管理操作。
- 注册提交邮箱、密码、邀请码。相同规范化邮箱只允许一个正式账号；不去除邮箱中的加号后缀、不套用单个邮箱服务的点号规则。第一版明确按不区分大小写匹配登录邮箱，并使用标准邮箱格式校验。
- 邀请码名额在邮箱验证、账号激活时占用，未验证申请不消耗永久名额。验证时再次检查码的有效期、撤销状态及剩余名额。
- 验证事务内锁定或原子更新邀请码使用数，与账号激活、验证令牌消费一起提交。两个并发验证不能超过 max_uses，同一令牌或账号重复提交不能重复计数。
- 待验证申请 24 小时过期，不创建可登录的激活账号。单封验证令牌 30 分钟有效，可限流重发；重发不允许覆盖申请中的邮箱、密码，也不能修改已有账号。
- 名额已满、已撤销或已过期时不会激活账号，给出明确邀请码失效提示。旧申请过期后可以重新申请；旧申请未过期时，只有持有该申请有效验证令牌的用户可以换用新邀请码，否则不能借重新注册覆盖申请或密码。
- 发信响应区分“请求已受理”与邮件服务接受投递，不将后者冒充收件人实际收到。发信服务未配置或整体不可用时统一提示服务暂不可用；不把开发用收件箱当真实送达。
- 注册、登录、重发与找回密码不给出足以枚举已有账号的差异化响应。验证码、完整邮箱、密码和邀请明文不得出现在公共日志中。

## 5. 密码、邮件与登录会话

- 密码 15–128 个字符，不自动裁剪，不强制固定大小写组合；使用成熟 Argon2id 库，至少达到 OWASP 推荐的 19 MiB、2 次迭代、并行度 1。不得用普通 SHA-256 保存密码。
- 验证和重置令牌使用高熵随机值，库中只存摘要，分别绑定用途、目标和过期时间，不能互相代用。
- 找回密码请求使用统一“请求已受理”响应，不按邮箱是否存在、实际投递是否成功产生可枚举的差异；投递失败记录受限日志并支持限流重试。重置令牌 30 分钟有效、一次使用。密码重置后撤销该账号全部旧会话，不自动登录。
- SMTP 配置包括主机、端口、TLS 模式、用户名、凭据、发件地址及站点基础地址；凭据通过环境配置，不提交到 Git。
- 发信设置连接和读写超时；失败不泄露凭据或供应商内部响应。测试用注入式收件箱仅用于隔离测试，不在生产返回邮件令牌。
- 使用数据库保存的可撤销随机会话，客户端仅有不透明 Cookie。会话摘要关联服务端 user_id，不把角色或 user_id 当客户端可信声明。
- 生产 Cookie 设置 HttpOnly、Secure、SameSite=Lax、Path=/，不配置宽泛 Domain；统一 HTTPS 同源部署。会话绝对期限 7 天，空闲期限 24 小时。
- 登录后换发会话以防会话固定。退出撤销当前会话；重置密码、禁用账号撤销全部会话。过期会话返回 401。
- 所有改变状态的请求（包括登录、注册、退出）需 CSRF 保护和严格来源校验。前端先获取服务端建立的短期匿名/登录会话对应 CSRF 令牌，再随写入请求提交；不能仅靠 SameSite。

## 6. 所有权与共享数据权限

- users 保存身份及激活/禁用状态；watchlists.owner_id 关联用户且对正式分组不能为空。
- 当前用户始终来自服务端会话依赖。请求中的 owner_id/user_id 等字段被拒绝，不能通过伪造所有者或管理员字段授权。
- 自选分组列表、单组股票列表、创建、重命名、删除、添加及移除股票全部检查归属。查询条件含 owner_id，写入事务中同样约束归属。
- 对另一个用户的分组统一返回 404，避免通过分组 ID 确认其存在；匿名私有操作返回 401。
- 行情驾驶舱只聚合当前用户所属分组的股票；公共指数与行情读取不携带任何人的分组信息。第一版工作台行情查询也要求登录，并有行情请求限制。
- Stock 与 DailyPrice 是共享市场资料，不按用户复制。普通用户只能关联股票，不允许用客户端名称覆盖共享股票元数据，也不能通过自选添加任意导入共享资料；未知股票需可信数据导入流程就绪，否则返回不存在。
- 日线导入只允许管理员。普通用户不能修改共享价格、生成邀请码或提升自身角色。
- Agent 聊天与 risk-summary 要求激活登录账号。只读股票工具可查询共享市场数据，模型与模型参数无权选定当前身份。
- 新 HTTP Agent 运行及工具审计绑定服务端 user_id；任何未来 HTTP 审计读取按用户过滤，run_id 本身不是访问凭据。现有离线 CLI 审计可以保持系统记录，不向普通用户开放。
- 模型输出仍是非可信建议；新增用户认证不改变 Day13 白名单、严格参数和最大轮数约束。

## 7. 旧数据库迁移

- 先做备份并在测试数据库验收，提供显式、可重复执行的迁移命令；不在启动时自动认领分组，也不自动执行正式库升级。
- 管理命令指定经过验证的管理员账号，将旧个人自选分组一次性归属到该账号。新用户默认没有旧分组，不允许“第一个注册的人”自动取得旧数据或管理员身份。
- 历史无用户审计保留为系统历史，不猜测其用户，不展示给普通账号；新 HTTP 运行必须有用户归属。
- 所有者外键、邀请码次数约束、邮箱唯一约束和时间有效性在数据库/事务层保障。重复迁移不重复分配、不破坏市场价格与已有关系。
- 全部私有分组完成归属后启用非空约束；未完成迁移时生产启动明确拒绝私有业务服务，不能静默回退到全局列表。

## 8. 前端流程与建议确认

- 保留现有 TURAQ 视觉和分钟行情功能。添加登录、注册（邮箱/密码/邀请码）、邮件验证、重发、找回与重置页面，以及账号与退出入口。
- 前端请求统一使用 /api 相对路径；开发代理统一到实际后端端口。401 时停止私人数据刷新、清空当前用户视图和聊天内存并进入登录流程，不把账户 A 的内容带给账户 B。
- 来源展示区分 executed_at 与 latest_trade_date，空来源和未知上游如实展示。执行响应的 error/status 仍以后端为准。
- suggestions 作为独立卡片保存与展示，明确“建议，尚未执行”。用户点击操作后，从本人分组中核对目标，确认框展示分组、股票和具体影响。
- 只有用户点击确认才构造新的 ExecutionRequest；不整包透传模型 JSON，不接受模型的 confirmed=true。
- 服务端仍按会话、归属、目标存在性与事务结果授权和执行；前端确认不能替代后端检查。
- 操作进行中禁用重复提交。确认取消不发请求；成功才刷新本人分组及行情列表。失败保留错误和建议。
- 网络超时显示“结果待确认”，先重新查询目标状态，不自动重复写入，也不把仅查询到的缺失状态冒充原请求执行成功。
- 为明确动作增加持久化审计：服务端用户、操作、目标、时间和真实结果；越权尝试受限记录，不向调用者泄露他人数据或敏感原始错误。

## 9. 内测额度与生产条件

- 邀请码控制人数，不能替代限流。所有限流/计数使用跨进程共享的 PostgreSQL 状态或独立共享存储，不能只有单进程内存计数。
- 建议初始登录失败限制：同 IP 15 分钟内 20 次、同账号 15 分钟内 5 次，冷却后可重试。注册及邮件请求每 IP 每小时最多 10 次，同邮箱重发间隔至少 60 秒、每天最多 5 次。匿名邮件错误不暴露账号是否存在。
- 模型入口覆盖 agent/chat 与 risk-summary：每用户每日 20 次研究请求、每分钟最多 2 次、同时最多 1 次；站点每日实际模型 HTTP 调用上限 200 次，包含重试。额度在请求/调用发出前原子预留，失败请求计入尝试；正常退出释放并发占用，超时租约有界过期。
- 模型输出设可配置的有限长度、HTTP 超时与总处理期限；保持最多 5 轮，禁止无限重试。限额/暂停模型开关命中时模型客户端不能被调用。上述次数控制不是精确人民币账单上限。
- 超额返回 429 及 Retry-After，无法检查共享额度时拒绝模型调用；不得因计数服务故障降级为无限调用。
- 行情数据保持现有真实来源、缓存和分钟接口，增加登录用户/IP 的有界请求控制；10 秒前端刷新应在正常额度内。
- HTTPS、同源 API、明确可信代理设置、正确环境变量及非通配凭据 CORS；不对外暴露数据库端口。异常响应不返回堆栈、数据库密码或模型密钥。
- 本轮仅准备和本地/隔离验收，不隐含购买服务、发送邀请、修改 GitHub 可见性、推送代码或正式部署。

## 10. 验收标准

1. 用两个账号完整走注册、真实邮件验证、登录、自选 CRUD、行情与研究流程；注册未验证账号不能进入工作台。
2. A 的列表与行情聚合不包含 B 的自选。B 猜中 A 的分组 ID，也无法读取、重命名、删除、添加或通过 Agent 动作移除股票。
3. 超额、过期、撤销、复用验证令牌及邀请码并发验证都被正确拒绝；50 个名额不能激活第 51 个账号。
4. 退出后的旧 Cookie、过期 Cookie、密码重置前 Cookie 不能继续访问。错误来源与缺失/错误 CSRF 令牌不能写入。
5. 取消建议不发请求，模型声称确认不执行，越权建议不执行，失败/超时不显示成功，重复点击只产生一次在途请求。
6. 发信服务未配置/整体不可用有统一提示，单次投递失败有受限可查记录且没有“已收到邮件”等假成功；找回响应不枚举账号，重置与验证令牌不能串用。生产模式不能显示开发令牌或使用虚假发信通过验收。
7. 两个服务进程并发时用户和站点额度仍正确；限额拒绝、认证拒绝及权限拒绝不会调用模型。
8. 显式迁移在旧测试数据上通过，重复运行不破坏关系、价格和审计，普通新用户看不到历史私人分组。
9. 保持市场、工具循环、审计及现有价格精度回归；浏览器验收桌面与移动端，不出现账户切换残留或登录页溢出。
10. 真发信与少量真实模型验收须在接通服务后明确执行并记录；隔离测试通过不能被描述为已经上线。

## 11. 设计依据

- OWASP Authorization Cheat Sheet：后端默认拒绝，逐请求授权，不能把可猜测 ID 当权限。https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html
- OWASP Session Management Cheat Sheet：服务端会话、Cookie 属性、到期与撤销。https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html
- OWASP Password Storage Cheat Sheet：使用 Argon2id 等适合密码的算法。https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html
- OWASP Forgot Password Cheat Sheet：一次性有时限令牌、统一回应与请求限制。https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html

自查：已区分邀请码与邮箱验证令牌、已验证激活与发信成功、共享市场数据与私人自选、技术基线与正式上线。具体邮件供应商及部署域名是外部接入配置，不是假定已具备的能力；没有这些配置不得开放注册内测。
