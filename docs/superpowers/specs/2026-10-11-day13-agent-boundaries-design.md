# Day 13 第一阶段：聊天入口与只读工具边界

用户已批准沿现有实现分阶段补齐安全边界；本阶段由当前会话直接实施。原总计划为上级目录的 `8-week-agent-learning-roadmap.md`，Day 13 为安全边界。来源元数据和建议/执行类型分别属于后续阶段。

## 目标与契约

`POST /api/v1/agent/chat` 接受前端的 user/assistant 文本历史。后端在最前面插入自己维护的 system 消息。文档、工具数据、用户文字及客户端提供的历史均不能授权新工具或写入业务数据；提示词作为说明，执行权限由现有三工具白名单控制。

- 消息 1–20 条；每条 content 为严格字符串，最多 4000 字符，不能全为空白；总 content 最多 20000 字符。
- role 只允许 user/assistant，最后一条必须是 user；消息和请求拒绝额外字段，客户端不得上传 tool_calls、tool_call_id、系统权限或工具定义。
- max_rounds 为严格整数 1–5，默认 5。非法请求返回 422，发生在模型创建和数据库会话建立之前。
- 后端系统说明明确只读/计算工具、数据与指令边界、建议不产生执行权限；不把模型文本中“已经执行”的说法当成执行证据。
- 保留当前三个工具、工具参数校验、模型/工具回传和数据库审计方式。越权调用返回 unknown_tool，参数拒绝返回 invalid_arguments，不修改自选股或股票资料。
- 工具请求的 arguments 非法 JSON、非对象 JSON 或无法安全序列化时仍能作为原始字符串返回错误轨迹；正常对象 arguments 仍按原响应返回字典，避免响应转换覆盖已经产生的拒绝记录。

这些是请求内容的应用级限制，不等于 HTTP 字节大小限制、身份认证、速率限制、模型输出可信保证或完整提示注入防护。模拟账户尚未实现，本阶段验证现有数据库业务表不发生修改，不声称已经测试不存在的账户引擎。

## 文件边界

`app/agent_policy.py` 集中请求约束、系统说明和历史构造；`app/agent_api.py` 使用该契约并安全展示原始参数。`tests/unit/test_agent_safety.py` 用真实循环、执行器、审计仓储和内存 SQLite 连接起来，模型为离线脚本响应；网络入口在测试中禁止调用。

## 验收

非法角色、字段、数量、内容和轮数均在模型/数据库之前拒绝；正常 user/assistant 历史保留内容顺序且 system 位于最前；即使脚本模型要求删除分组、修改账户或注册工具，执行器拒绝并落库，业务表内容不变。合法计算继续得到 -10.0000。非法 JSON 工具参数返回可查看的 error 记录。测试不连接正式数据库、不请求真实模型。

设计自查：范围为入口和现有只读执行路径；来源和交易执行后续建设，未用提示词替代权限检查。数字、字段和失败状态在本文件固定。
