# OpenViking 组合接入结果

已接入现有应用，采用“OpenViking 原生文件上下文 + 现有证据排序、核验和严格评分”。这是文件检索与主动保存研究偏好的首版，未启用语义向量检索、自动摘要或聊天记忆提取。

## 实现范围

财报评测只镜像原有茅台、平安固定公开报告的 7 个授权页。服务器先限定本次上下文的证券、披露日期与页面，使用独立原生账户、内容寻址文件和完整原文比较，之后才调用原有片段选择和证据 ID 机制。检索结果不授予权限，也不改变参考值、单位判定或通过率。

原生文件 grep 使用现有指标别名和词语作为候选召回。原始 PDF 的指标名称会被换行及数值单元格打断，完整简称或完整别名无法覆盖这些情况；候选召回因此使用与现有排序一致的词语，仍由原有排序、原文位置和严格评分控制最终证据。最初有 3 项回退的运行保留在 `evaluations/turaq/context-combination/functional-initial.json`，不是被改写的模型评分。

研究偏好位于“系统设置 → 研究与风险 → 长期研究偏好”。三个固定选项按登录账号保存，下次研究读取，以用户数据加入对话。没有聊天归档、私有文件上传或自由文本指令持久化。清除操作使用经读回确认的空记录，不宣称擦除原生文件版本历史。

## 费用和服务隔离

独立 OpenViking 0.5.2 服务使用新存储目录，没有复用或修改历史实验存储。应用通过带随机挑战的签名确认专用本地服务，所有模型请求均由本地端点拒绝。启动子进程时去除代理和外部模型密钥，并显式绕过本机代理。

原生目录初始化仍会产生向量请求；冷启动初期确实观察到这些请求被拒绝，不能说原生请求数为零。最终暖启动验收中的拒绝数见原始 JSON，外部提供商调用为零。文件写入和偏好清除均延迟处理，不生成可供语义检索使用的向量；不把这一结果当作 OpenViking 语义能力的质量验收。

## 验证

- 全部安全单元测试：814 通过，3 个已有依赖弃用提示。
- 隔离登录、CSRF、账号和模型额度相关测试：30 通过。
- 前端测试：87 通过；Vite 构建通过，新增控件实际包含在构建资源中。
- 定向测试包含实际隔离运行环境中的同步与异步 SDK 传输检查；在设置恶意代理环境后，未发起网络请求，确认两个模型客户端仍使用直连连接池。
- 原生服务结果见 `evaluations/turaq/context-combination/functional.json`：10 项检查全部通过，包含偏好跨客户端和重启读取、原生账号隔离、授权原文检索、原生镜像被改动后的回退、停服后的回退、重启后直接读取所有预期页面，以及固定的 52 个历史方法文件摘要验证。故障注入只修改合成账号的原生镜像，原文已恢复，未改动参考语料。
- 前后端已启动。健康接口和新路由可访问，未登录读取偏好返回 401。没有替用户设置实际研究偏好，没有额外调用模型计算新准确率。

## 独立审查

一次独立审查给出 0 Critical、2 Important、1 Minor。两项 Important 已用 RED→GREEN 回归修正：继承代理绕过本地端点，以及持久化验收自动补写导致的假阳性。之后未重复派发审查。

按执行约定记录并延后 1 项 Minor：专用健康端点如果异常返回非 ASCII 字符串签名，`compare_digest` 可能抛出类型异常，未必按预期回退。正常专用端点只生成十六进制签名；应用在验证完成前不会发送原生密钥或资料。该边界仍需后续处理。

使用及停用方式见 `docs/openviking-context.md`。当前接入结果不代表新增了模型准确率，也不改变此前对 OpenViking 与自有检索实验的结论。
