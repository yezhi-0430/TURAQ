# UI 结构设计方案

基于视频参考的视觉风格，结合项目现有功能设计的前端架构。

## 一、视觉参考总结

从视频中提取的设计特征：

**色彩系统**
- 深色主题：近黑背景 (#0A0D12 到 #161D2B 的渐进层级)
- 强调色：金色/黄色用于涨跌正值、绿色用于按钮/标签、红色用于风险警告
- 文本：浅灰到白色的层级，重要数据用高对比度

**布局特征**
- 左侧固定导航栏（约 200px）
- 顶部状态栏显示市场指数和账户信息
- 主内容区使用 Grid 布局，卡片式模块
- 数据表格占据大部分视觉空间，带分页和筛选

**交互模式**
- 标签页切换内容区域
- 数据表格支持排序、分页
- 表单使用深色输入框，圆角设计
- 按钮为圆角胶囊形状

#### 页面 1：行情驾驶舱（默认首页）

**用途**：快速概览市场和自选股状态

**布局**（Grid 2列）：

```
┌─────────────────────────────────────────┐
│  市场概览卡片                            │
│  (上证/深证/创业板 实时指数)              │
├─────────────────────────────────────────┤
│                                         │
│  自选股实时价格表格                       │
│  (代码 | 名称 | 最新价 | 涨跌幅 | 成交量) │
│                                         │
│  [点击行跳转到该股票详情]                 │
├─────────────────────────────────────────┤
│  最近风险线索                            │
│  (时间 | 股票 | 风险等级 | 摘要)          │
└─────────────────────────────────────────┘
```

**数据来源**：
- 自选股列表：`GET /api/v1/watchlists`
- 价格数据：`GET /api/v1/stocks/{code}/prices?days=1`
- 风险线索：后续实现的风险摘要历史记录

#### 页面 2：自选管理

**用途**：管理自选股分组和成员

**布局**：

```
┌─────────────────┬───────────────────────────┐
│  自选股分组列表  │   当前分组的股票列表        │
│                 │                           │
│  ○ 全部         │   代码 | 名称 | 加入时间    │
│  ○ 默认自选     │   ─────────────────────   │
│  ○ 科技股       │   000001 | 平安银行 | ...  │
│  ○ 新能源       │   [删除]                  │
│                 │                           │
│  [+ 新建分组]   │   [+ 添加股票到当前分组]   │
└─────────────────┴───────────────────────────┘
```

**功能映射**：
- 获取分组：`GET /api/v1/watchlists`
- 创建分组：`POST /api/v1/watchlists`
- 添加股票：`POST /api/v1/watchlists/{id}/stocks`
- 移除股票：`DELETE /api/v1/watchlists/{id}/stocks/{code}`

#### 页面 3：AI 研究助手 ⭐️ **核心展示页面**

**用途**：展示 Agent 工具调用和推理过程

**布局**：

```
┌─────────────────────────────────────────────────────────┐
│  对话历史区域（聊天界面）                                 │
│                                                         │
│  [用户] 平安银行从 10 元跌到 9 元，跌幅是多少？           │
│                                                         │
│  [Agent 思考中...]                                      │
│  ├─ 🔧 调用工具：calculate_change                      │
│  │   参数：old_value=10, new_value=9                   │
│  │   结果：-10.0000%                                   │
│  │   耗时：0.023s                                      │
│  └─ ✅ 执行成功                                         │
│                                                         │
│  [Agent] 平安银行从 10 元跌到 9 元，跌幅为 -10.00%。     │
│                                                         │
├─────────────────────────────────────────────────────────┤
│  输入框：请输入问题...                    [发送]         │
└─────────────────────────────────────────────────────────┘
```

**展示内容**：
- 用户输入与 Agent 回复的对话流
- **Agent 执行轨迹可视化**：
  - 工具选择
  - 参数传递
  - 执行结果
  - 执行时间
  - 成功/失败状态
- 支持多轮对话

**接口映射**：
- 当前使用 agent loop 的演示逻辑
- 未来对接：`POST /api/v1/agent/chat`（需新增）

**关键价值**：
这个页面直接展示你的 Agent 核心能力——多轮工具调用、结果回传、自动循环。面试官能清楚看到工具执行的完整流程。

## 三、技术栈建议

**前端框架**：React 18
**状态管理**：React Context + useState（项目规模不需要 Redux）
**样式方案**：CSS Modules + 自定义设计系统
**HTTP 客户端**：fetch API
**构建工具**：Vite

**不使用的技术**：
- ❌ TypeScript（保持简单，面试时间有限）
- ❌ UI 组件库（Ant Design / MUI）—— 自己实现展示设计能力
- ❌ 复杂状态管理（Redux / Zustand）

  --text-tertiary: #6B7280;   /* 禁用文本 */

  /* 圆角 */
  --radius-sm: 6px;

  --space-xs: 4px;

## 六、与视频的差异说明

**不实现的内容**（视频中有，但项目不需要）：
- ❌ 实时 K 线图表（项目只处理日线数据）
- ❌ 量化策略回测（项目专注风险监控和 Agent）
- ❌ 策略编辑器（项目不涉及策略开发）
- ❌ 实时交易下单（项目仅模拟交易）

**保留的视觉风格**：
- ✅ 深色主题色彩系统
- ✅ 数据表格的布局和排版
- ✅ 卡片式模块设计
- ✅ 左侧导航 + 顶部状态栏结构

当面试官查看你的 UI 时：

1. **直接打开 AI 研究助手页面** —— 这是你的核心竞争力
2. **演示一次完整的 Agent 对话** —— 让他们看到工具调用的可视化
3. **打开自选管理** —— 证明 API 对接和 CRUD 能力
4. **展示风险监控** —— 展示结构化输出的验证

**说明要点**：
- "这个 UI 参考了量化交易平台的视觉风格，但功能完全基于我的项目实际能力"
- "Agent 工具调用的可视化是我自己设计的，能清楚展示工具选择、执行和结果回传的全过程"
- "深色主题和数据表格设计都是手写 CSS，没用组件库"
