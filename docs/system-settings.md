# 系统设置部署与运行

个人配置保存于 `personal_settings`，全站配置保存于 `global_settings`，管理员变更记录保存于 `settings_audit`。不修改既有业务表结构。部署前备份数据库并安装项目依赖，再执行现有建表入口：

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
.\.venv\Scripts\python.exe -c "from app.database import create_tables; create_tables()"
```

这是其他部署环境的显式部署步骤。当前本地环境已在 2026-10-16 完成数据库备份，并仅新增上述三张设置表；没有修改既有账号、模型密钥或业务记录。备份保存在被 Git 忽略的 `.local-backups/settings/`。已有数据库的账号/所有权升级仍遵循 `app.schema_upgrade` 的原有流程。

全站可编辑设置覆盖同名部署环境配置，每次请求读取数据库，因此保存后无需重启。删除密钥覆盖（提交空字符串）会恢复部署的 `DASHSCOPE_API_KEY`；其他设置的“恢复默认”使用当前部署默认值。版本号防止旧页面覆盖新修改，冲突返回 409，重新加载后再保存。个人设置按当前账号隔离。退出其他会话保留当前会话；修改密码验证旧密码并撤销全部会话和未使用的密码重置令牌。

## 模型密钥

服务端必须通过部署环境注入有效的 `SETTINGS_ENCRYPTION_KEY`（Fernet URL-safe base64 key）才能修改密钥。可以在安全的部署终端生成一次并存入部署秘密管理器：

```powershell
.\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

不要提交此值到版本库，不要通过页面传递此值。设置环境后重启服务；缺失或格式无效时，界面允许查看配置状态，但密钥编辑返回 503，说明部署方法。数据库只保存 Fernet 密文；响应、导出和审计不含密钥，审计只记录 updated/cleared。部署密钥需要与数据库备份一起可靠保管；直接更换加密密钥会导致原密文不可读，管理员仍可登录并重新写入模型密钥。

当前本地环境已生成独立的加密密钥并写入被 Git 忽略的 `.env`，没有回显或写入文档。没有替换 `DASHSCOPE_API_KEY`，后续可在管理员设置中使用加密更新入口。

## 使用方法

登录后打开左侧“系统设置”。普通用户拥有五个分类，管理员另有四个全站分类：

| 分类 | 功能与生效范围 |
| --- | --- |
| 工作台偏好 | 默认进入页面（下次登录首次进入生效）、舒适/紧凑密度、减少动画、自选组内名称/代码排序 |
| 行情与图表 | 自动刷新与 10/30/60 秒间隔、行情详情默认周期、个股复权方式；隐藏页面暂停轮询 |
| 研究与风险 | Enter 或 Ctrl/⌘+Enter 发送、研究轮数上限、风险等级/处理状态筛选、公告回溯范围 |
| 模拟交易 | 开市时自动刷新与间隔、新账户初始资金/佣金/最低佣金、委托默认类型；已有账户和成交不变 |
| 账号与安全 | 账号信息、修改密码、查看当前及其他有效会话、退出其他会话 |
| 模型服务（管理员） | 模型开关、供应商与名称、分业务输出预算、加密更新密钥 |
| 配额与访问（管理员） | 用户/全站滚动调用额度、行情和搜索请求限流、新建模拟账户数量上限 |
| 运行与诊断（管理员） | 单次/总处理超时、全文分批大小、数据库和服务配置状态 |
| 变更记录（管理员） | 分页查看全站配置修改人、时间和变更内容，密钥只显示更新动作 |

所有表单通过“保存设置”生效；“恢复默认”先填入草稿，确认保存后生效。个人 JSON 导入同样先生成草稿，不会立即覆盖配置。导出只包含已保存的配置，不包含账号信息、密钥或未保存的修改。版本冲突时保留当前草稿，记下需要的修改后重新加载最新版本。

管理员拥有普通用户的个人设置。管理员的个人偏好不影响其他用户，只有明确标记“ADMIN / 全站管理”的分类会修改全站策略。

诊断执行真实 `SELECT 1`；模型与邮件项只报告部署配置状态，不声称网络验证，也不发送模型或邮件请求。

## 验证范围

`tests/auth/test_settings.py` 使用内存 SQLite 验证鉴权、CSRF、完整配置与严格类型校验、版本冲突、运行时模型与账户数量配置、密钥写入/清除与脱敏、用户隔离、恢复默认、会话撤销、密码变更及限流。PostgreSQL 部署仍需执行上述新增表步骤。
